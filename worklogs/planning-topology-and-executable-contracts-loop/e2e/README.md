## Ownership (CT88 / CT89, and section 2 of the handoff design)

1. **Planner** records the E2E obligation and the observable oracle before coding. The
   index and the master sheet are planner artifacts; the oracle text in them is copied
   from the register, not written here.
2. **Coder** appends an implementation handoff (facts vs proposals). It may implement
   fixture/helper files **named in the reviewed plan**. It never assigns or approves a
   live result.
3. **Independent reviewer** completes the manual checklist (SLICE6 STEP7) **before**
   the fixture package (STEP8). The planner's own self-check is not this review.
4. **Operator** runs the copy/paste instructions on the deployed host and supplies the
   run identifiers and evidence.
5. **Operator or independent evidence reviewer** records the live result. Neither a
   harness nor an eval role sets it.

## Result vocabulary (Q63, E231; artifact schema section 6)

Exactly `NOT RUN | PASS | FAIL | BLOCKED`. `commentary` is optional in every state,
<=512 UTF-8 bytes, single line, credential-redacted, never control flow.
`NOT RUN` and `BLOCKED` never count as `PASS`. Local proof and live result are
recorded separately: a green in-repo suite is not a deployed-host verdict.

## How to record an attempt

1. Open `I03/live-verification.md` and go to the case's `#### Attempts - <ID>` table.
2. **Append one row.** Never edit, reorder or delete an existing row; attempts are
   append-only and a superseded attempt stays legible.
3. Fill the identity columns CT88 requires: `#`, `Date`, `Result`, `Run ID`,
   `Deployed SHA`, `Image digest`, `Profile`, `Config`, `Command`, `rc / effect`,
   `Evidence`, `Reviewer`, `Commentary`. An empty `Commentary` is valid.
4. Set the case's `Live result` field to the **latest** attempt's result, and mirror it
   into this index's `Result` column.
5. Keep evidence references small: a path under `notes/evidence/` or a run id. Do not
   paste secrets or large host logs into this directory.

`tests/test_e2e_artifact_contract.py` validates the JSON Schema with all four states
(commentary present and absent, including the UTF-8 byte limit), then checks the
index/master case IDs, current NOT RUN states and declared attempt columns. It does
not parse or evaluate host evidence and never assigns a live result.

## I02 origins

No `I02/` subdirectory exists in this project package; the I02 producer origins are the
early sections of the register itself (`## SLICE1 - the command runner`,
`## SLICE2 - kill directives`, `## SLICE4 - the mutation sandbox`,
`## SLICE6 - workflow composition and post-eval gate reconciliation`). Those are I02
shipping-ownership artifacts, not I03's. This index retains the **origin pointer**
(the `Register origin` field in the master sheet) rather than copying I02 rows, so no
I02 shipping claim is inherited and no unique producer case is lost.

## Non-goals

- No live-host execution is claimed, scheduled or implied here.
- No fixture, helper or run sheet exists yet: SLICE6 STEP8 follows the STEP7 review.
- This package does not create a staging host or change the main-only deployment flow.
