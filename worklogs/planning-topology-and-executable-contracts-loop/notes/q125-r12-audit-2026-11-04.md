**Status:** READ-ONLY AUDIT — no runtime/test code changed. R12 and W0 remain
OPEN. This note records facts, risks, and a recommendation for Q125; it is not
implementation authorization and does not close R12 or W0.

**Scope:** Q125, the R12 S4P1 row, Q113's strict W0 exit, the scope-reduction
audit, and the optional FastAPI/runtime extra.

### 1.2 R12 row and Q113

- R12 row (`notes/i03-execution-call-inventory.md:86`): producer is the optional
  runtime server; inspected caller/dependency is "optional runtime server";
  required route/negative oracle is the component C1 tests
  (`tests/test_runtime_server_c1.py`), with the HTTP transport stubbed.
- The 2026-11-04 rerun: 9 passed, 6 skipped (all six C1 cases; runtime-server
  extra deferred). No non-skipped managed-backend negative oracle through a
  reachable production caller is evidenced.
- Q113 (strict row closure): W0 cannot exit until every S4P1 row's named
  managed-backend negative oracle passes through the production caller. A
  helper-only test, source scan, absent tool, or skipped oracle cannot close a
  row.
- The scope-reduction audit classifies the server as cell-internal/optional and
  explicitly says the future remote client is not a security component: it has
  no approved-profile launch, ownership fencing, process-tree stop, or sealing.

### 1.3 Q125 options

- A: keep the runtime optional; narrow R12 to the reachable production boundary;
  local test through the actual managed CLI/chat caller with the optional server
  unavailable; treat HTTP client/server tests as component-only; make no claim
  that `RemoteRuntimeExecutor` is wired or secure.
- B: keep Q113 strict and defer R12 pending a separately approved integration;
  do not add a caller; define an approved production composition first.
- C: explicitly defer/exempt R12 from the W0 all-row exit; amend Q113 and the
  increment's W0 exit.

## 2. Can option A give an R12-specific managed-backend negative oracle through the production caller?

**Yes, but only as a negative/absence oracle — not as a positive exercise of the
optional server.** The production managed caller never uses
`RemoteRuntimeExecutor`; the optional server is not in the managed path. An
absence oracle can prove that the production managed caller does not use the
optional runtime and does not fall back to a host shell when the optional server
is unavailable. It cannot prove the optional server's refusal behavior; the
component C1 tests remain component-only.

## 3. Gaps in the verifiability of the absent FastAPI/runtime extra

- The optional server is not started by `fa run`; `fa.runtime.__init__` sets
  `app=None` if FastAPI is not installed. The production `fa run` does not use
  it.
- `RemoteRuntimeExecutor` is only in `src/fa/runtime/bash_executor.py`; no
  production caller. The `run_bash` resolver uses `InProcessPtyExecutor`.
- The R12 C1 tests stub the HTTP transport; they are component-only. The 6 C1
  tests are skipped because the runtime-server extra is deferred.
- The absence test must be non-skipped and must not require the runtime-server
  extra; it must use the production caller and assert zero
  `RemoteRuntimeExecutor` usage, zero FastAPI server starts, zero host
  subprocesses, zero proxy credentials, zero project writes.
- The absence test must cover the managed path, not the legacy host path. The
  managed path uses `ManagedBashExecutor`; the legacy path uses
  `InProcessPtyExecutor` (host PTY). The R12 Q113 row oracle is the managed path.
- The absence test must be a C1/C2 test; the R12 component C1 tests remain
  component-only. The Q113 row closure would be based on the absence test; the
  R12 component C1 tests are a separate component gate.
- The absence test must not claim the optional server's security; the optional
  server is cell-internal/optional; `RemoteRuntimeExecutor` is not a
  production/security authority.
- The absence test must not be a helper-only test; it must use the production
  `drive_session`/registry. A helper-only test, source scan, absent tool, or
  skipped oracle cannot close a row under Q113.
- The absence test must be a non-skipped managed-backend negative oracle; it must
  run against a real local supervisor that refuses EXEC; the managed path returns
  a structured unavailable result; no host fallback.
- The absence test must assert zero host subprocesses; the managed path uses the
  supervisor's cell; the host does not spawn a shell.
- The absence test must not use the legacy host path as the primary oracle; the
  legacy path is a host path, not a managed backend.

## 4. Risks

- **Option A is a narrowing of R12's acceptance.** The absence oracle proves the
  production caller does not use the optional runtime; it does not exercise the
  optional server's code. The R12 component C1 tests remain component-only.
- **The absence oracle is a negative oracle.** It cannot prove the optional
  server's refusal behavior; it can only prove the production caller does not
  use it and does not fall back to a host shell.
- **`RemoteRuntimeExecutor` must not become a production/security authority.** It
  has no approved-profile launch, ownership fencing, process-tree stop, or
  sealing. It must not be wired into the production path or treated as a managed
  execution authority.
- **The optional server is cell-internal/optional.** The scope-reduction audit
  classifies it as such; the absence oracle is consistent with that
  classification, but it does not make the server a production component.
- **The R12 component C1 tests are skipped.** The 6 C1 tests are skipped because
  the runtime-server extra is deferred; the absence test must not be skipped and
  must not require the extra.
- **The Q113 strict row closure is a process requirement.** The absence test
  satisfies the production-caller requirement, but the R12 component C1 tests
  are a separate component gate. The operator must decide whether the absence
  test is sufficient for R12 row closure or whether R12 should be deferred.
- **Option B is safer if the operator wants to keep Q113 strict and not narrow
  R12.** It defers R12 pending a separately approved integration; W0 remains open
  until that work is authorized and completed.
- **Option C is a last resort.** It explicitly defers/exempts R12 from the W0
  all-row exit; it requires an explicit Q113/increment amendment and must not be
  described as satisfying the original all-row condition.

## 5. Recommendation on Q125

**Option A with a precise absence oracle** is the only way to give an
R12-specific managed-backend negative oracle through the production caller
without reinterpreting `RemoteRuntimeExecutor` as a production/security
authority. The absence oracle should be a non-skipped C1/C2 test through the
production managed `fa run --role chat` with a real local supervisor that
refuses EXEC; it should assert zero `RemoteRuntimeExecutor` usage, zero FastAPI
server starts, zero host subprocesses, zero proxy credentials, zero project
writes; it should be explicit that the optional server is not wired or secure;
the R12 component C1 tests remain component-only.

If the operator wants to keep Q113 strict and not narrow R12, **Option B** is the
safer choice: defer R12 pending a separately approved integration, keep W0 open,
and do not add a caller. **Option C** is a last resort if the operator explicitly
accepts a revised W0 exit.

**Acceptance boundary.** This audit does not close R12 or W0. No runtime/test
code was changed. R12 and W0 remain OPEN. The proposed nodeid and counters are a
plan for a future test, not evidence.
