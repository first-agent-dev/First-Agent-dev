# W1 / Q97 managed-discovery resource contract — 2026-11-06

**Disposition.** E506 records the locally derived Q97 contract for managed `fs_search` and `fs_reach`. The values below are implementation limits, not approved-host measurements. Q111-A remains binding: crossing an aggregate work/index/output/time budget is explicit non-success, never a partial or truncated success. Q134 resolved the existing per-file boundary: files above the established 200,000-byte indexing ceiling remain a declared exclusion, counted and surfaced as skipped; they do not by themselves turn an otherwise in-budget discovery into a budget refusal. This preserves the existing `skipped_large_files`/`files_skipped` contract. It does not permit silently dropping candidates that exceed any aggregate quota.

**Amendment 2026-11-09:** operator selected 60 KiB for the complete serialized managed discovery ToolResult, superseding E506’s 30,000-byte output bound. This can exceed the model context budget; normal projection may elide and store an artifact. This decision does not change the other Q97 limits or constitute host acceptance.

The existing user-selected search/reach result limits, depth semantics, and documented oversized-file exclusions remain ordinary tool semantics. They are distinct from these resource budgets. A query hitting a resource budget is not converted into the existing `truncated=true` success path.

## Memory derivation

A synthetic 200,000-byte dense-assignment source (`"x=0\n" * 50_000`) produced 200,001 AST nodes and a 124,499,768-byte `tracemalloc` peak while running `ast.parse` and `StructuralIndex._walk_tree`. A near-limit dense-call fixture (200,001 bytes; deliberately one byte over the source ceiling) produced 99,999 nodes, 24,999 edges, and a 72,512,020-byte peak. The larger fixture peak is the formula input `P=124,499,768`; local traced allocation is not host RSS and is not an approved production limit.

`M_raw = 3P + 2S + I + D + C + O`, where `S=33,554,432` aggregate source bytes, `I=8,388,608` bounded candidate/path inventory allowance, `D=134,217,728` SQLite page ceiling, `C=16,777,216` SQLite cache ceiling, and `O=61,440` serialized ToolResult bytes. Thus `M_raw=600,053,160` bytes. Round **up** to the next 134,217,728-byte (128 MiB) quantum: `M_reserve=671,088,640` bytes = **640 MiB**. The factor of three on the synthetic peak is an explicit engineering margin; the source, index-page, cache, inventory, and output terms are separate caps, not inferred from RSS.

The source corpus probe (local checkout only, not production authority) found 1,615 walk entries; 1,081 search candidates, of which 1,075 were within 200,000 bytes and contained 20,211,272 bytes; and 582 Python reach candidates, of which 581 were within the per-file ceiling and contained 8,127,896 bytes. The largest valid Python candidate was 196,504 bytes; `src/fa/execution/workspace.py` is 256,012 bytes and is therefore an explicit skipped file under Q134. The under-ceiling Python corpus contained 929,624 AST nodes, 8,698 function/async-function definitions, 737 classes, and 54,485 call nodes. These measurements justify that the selected candidate/source/AST/index-count ceilings exceed this source sample with headroom; they do not establish production parity, approved-profile identity, host memory behavior, or host acceptance.

## Implementation and failure contract

Managed-only discovery must use a bounded incremental `scandir` inventory rather than first materializing `os.walk`'s unbounded per-directory lists. Count the full walk inventory and candidate set before search-result growth; stat sizes during preflight, then verify identities and actual byte counts through `RootedFileReader` as files are read. Keep the index one-shot and in memory (`Path(":memory:")` / `in_memory=True`), enforce page/cache bounds, and close it on every exit. Preserve legacy host-mode behavior.

Aggregate quota, rooted-read race, AST/cardinality/page, serialization, or deadline failure returns the existing `ToolResult` error shape with `search_failed` or `reach_failed`, stable sanitized reason, and `retryable=false`; it yields no paths/results for controller observation. Backend absence stays `execution_unavailable`; confirmed timeout stays `command_timeout`; uncertain identity, terminality, or transport stays `execution_unknown`. Search/reach output must never be shortened into success to satisfy a cap. Oversized per-file exclusions remain visible in the established skip field/count. No host Git, canonical project writes, second writer, host index, retry, or fallback is permitted.
