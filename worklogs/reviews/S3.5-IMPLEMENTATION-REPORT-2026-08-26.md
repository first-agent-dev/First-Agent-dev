## Problem Statement

S3 wrote `scope_estimate` events to `session.db` (event_log table) and `events.jsonl`, but three downstream consumers were blind to them:

1. **fa stats** — `scope_estimate` was in `PARSED_KINDS` (derived from `LogKind` minus `UNPARSED_KINDS`) but had no dispatch branch in `_parse_events`, causing two pre-existing contract tests to FAIL
2. **Blackboard** — events went to `event_log` table only, not `blackboard` table; `fs_blackboard_query` couldn't find scope estimates
3. **global_history.db** — `_extract_telemetry_from_log` ignored `scope_estimate` events; cross-run analytics couldn't see scope routing decisions

## Implementation Details

### 1. fa stats integration (src/fa/stats.py)

**Data model:**
```python
@dataclass(frozen=True)
class ScopeEstimateRecord:
    difficulty: int
    scope: str
    risk: str
    confidence: float
    recommended_mode: str
    task_preview: str = ""
```

**Dispatch branch** in `_parse_events`:
```python
elif kind == "scope_estimate":
    scope_estimates.append(
        ScopeEstimateRecord(
            difficulty=int(content.get("difficulty", 0)),
            scope=str(content.get("scope", "")),
            ...
        )
    )
```

**Render section** in `render_session`:


### 2. Blackboard write (src/fa/cli.py)

Added after the `log.append()` call in the scope estimation block:
```python
if state.blackboard is not None:
    try:
        from fa.blackboard.blackboard import BlackboardEntry

        bb_entry = BlackboardEntry.create(
            id=f"scope-estimate-{run_id}",
            type="scope_estimate",
            payload={...},
        )
        state.blackboard.write(bb_entry)
    except Exception as exc:
        logger.warning("scope_estimate blackboard write failed: %s", exc)
```

**Design choice:** Uses `BlackboardEntry.create()` which handles content_hash, toolchain_digest, timestamp, and all optional fields (read_set, write_set, etc. default to empty). The write is best-effort — if it fails, the event_log write already succeeded.

### 3. global_history projection (src/fa/inner_loop/global_history.py)

**Schema addition:**
```sql
scope_estimate_json TEXT NOT NULL DEFAULT '{}'
```

**Extraction** in `_extract_telemetry_from_log`:
```python
elif ev.kind == "scope_estimate":
    scope_estimate = {
        "difficulty": int(c.get("difficulty", 0)),
        "scope": str(c.get("scope", "")),
        ...
    }
```

The projection stores the LAST scope_estimate event per run (if multiple exist, the latest wins). This is correct for the chat role, which produces exactly one scope_estimate per session.
